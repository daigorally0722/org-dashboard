# 組織ダッシュボード（Org Dashboard）

四半期OKRを「会社 → 部門 → 個人 → 今週のタスク」まで一気通貫でつなぎ、
**ログインした人が“見るべきものだけ”を見る**組織運営システム。

## 起動

```bash
npm install
npm run dev
# http://localhost:3000
```

## 画面の流れ

1. **ログイン**（名前を選ぶ → 暗証番号）
2. ログインすると、その人の役職に応じた OKR カスケードが表示される：

```
会社OKR（全員に見える）
　↓
部門OKR（自部門＋管理者/代表に見える）
　↓
個人OKR（題目）… クリックで開くと ↓
　↓
今週のタスク（チェックボックス・優先度・担当・マニュアル）
```

各「題目（Objective）」はクリックで開閉し、開くと中身（KR・下位ノード・タスク）が出ます。

## 役職と「見える範囲」

| 役職 | レベル | 見える範囲 | 完了者の確認 |
|---|---|---|---|
| 管理者(admin) | 0 | 全部門・全員 | ○（誰が完了したか） |
| 代表・経営(exec) | 1 | 全部門・全員 | ○ |
| リーダー(manager) | 2 | 自部門の自分＋下位 | ○ |
| 社員(member) | 3 | 自部門の自分＋下位 | × |
| インターン(intern) | 4 | 自分のみ | × |

ルール：
- **会社OKRは全員に見える**。ただし他人（特に上席）の細かいタスクは見えない。
- **自分より下の立場は見える／上席のタスクは見えない**（同部門内、レベル値が自分以上のみ）。
- 他部門は管理者・代表以外には見えない。
- **チェックを押せるのは本人か管理者だけ**。上位者は下位のタスクを閲覧＋「誰がいつ完了したか」を確認できる（ロック表示）。

## ディレクトリ

| パス | 役割 |
|---|---|
| `lib/types.ts` | データ構造の中心。Row型はSupabaseテーブルと1:1（users/company_okr/departments/individuals/tasks） |
| `lib/data.ts` | シードデータ（会社→部門→個人→タスク、ユーザー、暗証番号） |
| `lib/auth.ts` | 簡易ログイン（→ Supabase Auth に置換予定） |
| `lib/tree.ts` | **見える範囲を計算**してツリーを組み立てる。★Supabase移行はここのクエリだけ差し替え |
| `components/AppClient.tsx` | 認証状態＋タスク完了状態（誰が完了したか）を持つ最上位 |
| `components/OkrTree.tsx` | 会社→部門→個人の開閉ツリー |
| `components/TaskRow.tsx` | 本人はチェック可／上位者は閲覧＋完了者確認 |
| `components/LoginScreen.tsx` | 名前＋暗証番号のログイン |

## AI週次生成 & Supabase 接続の道筋

- タスクは `assignee_id / week_of / completed_by / completed_at` を持ち独立管理。
  AIが日曜夜に翌週分を layer/個人ごとに再生成 → upsert できる。
- 移行手順：①`lib/types.ts` の Row 型を `create table` に落とす → ②`lib/tree.ts` の
  データ取得を Supabase クエリに差し替え → ③`AppClient` の `onToggle` を `tasks` の
  UPDATE に、`lib/auth.ts` を Supabase Auth に置換。
- UI は `BoardView` しか知らないため、データソースを変えても表示ロジックは不変。
